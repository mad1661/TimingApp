# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev      # Next.js dev server (localhost:3000)
npm run build    # production build (output: "standalone")
npm run start    # serve the production build
npm run lint     # next lint — the only automated check in this repo
npm run backfill # one-time historical scrape into Firestore (see below)
```

There is **no test framework** configured. Validate changes with `npm run lint` and by running the app (`npm run dev`). Regression checks are plain scripts: `npx tsx scripts/accutime-fixture-check.ts`, `npx tsx scripts/run-visibility-check.ts` (ignored-key matching, race days) and `npx tsx scripts/dataout-fixture-check.ts` (the getresults → RACEDATA export's tower conventions, synthetic fixtures). There is no ESLint config in the repo, so `npm run lint` stops at Next's setup prompt; `npx tsc --noEmit` and `npm run build` are the type checks.

`npm run backfill` (runs `scripts/backfill.ts` via `tsx`) must run **locally, not in the sandbox** — getresults.nhradata.com is firewalled there. It needs `NHRA_USERNAME`, `NHRA_PASSWORD`, and Firestore credentials (`GOOGLE_APPLICATION_CREDENTIALS` or the `FB_ADMIN_*` env vars). It checkpoints to `.backfill-progress.json` and is safe to re-run (writes dedupe).

## Stack & deployment

Next.js 14 App Router (React 18, TypeScript `strict`), Tailwind CSS v4 (theme tokens like `nhra-red`/`nhra-card` come from the `@theme` block in `src/app/globals.css` — **not** the vestigial `tailwind.config.ts`; see Gotchas), Firebase Admin SDK → Firestore. Deployed to Cloud Run via **Firebase App Hosting** (`apphosting.yaml`), which injects `NHRA_USERNAME`/`NHRA_PASSWORD` secrets and `FB_ADMIN_PROJECT_ID`. Import alias: `@/*` → `src/*`.

## Versioning

**Shipping is part of the job.** The user always wants finished work deployed and should not have to ask: merge the PR into `main` yourself (App Hosting builds and deploys from `main`) and report the version that went out. Don't leave completed work sitting in an open PR.

The app version shows in the navbar footer, sourced from `src/lib/version.ts` (`APP_VERSION`) and mirrored in `package.json` `"version"`. **Bump it on every change shipped to `main`** — patch (`1.1.1`→`1.1.2`) for fixes/small changes, minor (`1.1.x`→`1.2.0`) for features — and keep the two files in sync. This is how the user confirms a new deploy actually rolled out, so it is not optional.

## Architecture

### The data pipeline (read these files together to understand the app)

1. **Scrape** — `src/lib/scraper.ts`. NHRA timing data lives behind an ASP.NET WebForms site (`getresults.nhradata.com`). The scraper logs in and drives the ViewState/postback sequence (year → event type → event → optional date dropdown), then parses the `#runGridView` table into `RunRow[]`. It caches authenticated sessions (cookies + a warm ViewState) for ~10 min so polling can do a "fast refresh" without re-logging in.

2. **Persist + cache** — `src/lib/db.ts` is the **server-only** data layer (it imports `firebase-admin`; never import it from a client component). Runs are stored as **batched array documents** at `events_data/{eventCode}_{season}/run_batches`. db.ts keeps a **per-event in-memory LRU cache** (max 3 events, 30 s TTL). The TTL matters: the cache is per-Cloud-Run-instance, so without it one instance keeps serving stale data after another instance writes. `invalidateEventCache()` is called before scraping to force a reload.

3. **Dedupe** — every run gets `_dedup_key = timestamp|car|round|lane|event|season` (AM/PM stripped). `insertRuns()` only writes new/changed rows, so re-scraping is cheap and idempotent.

4. **Thrown-out runs** — ignoring a pass (Runs page, or *Throw out* in ET Finals) adds its dedup key to `ignored_runs/{eventCode}_{season}`; nothing is deleted. **`getVisibleEventRuns()` is the default data path**: the event's runs minus that list, keys compared normalized on both sides (`normalizeDedupKey`, so lists saved with 24-hour keys still match afternoon runs), and with `tag: true` AM/PM is inferred over the full set *before* filtering. Every page, stat, report, export, ladder, schedule and API reads it — a thrown-out pass is gone everywhere. The raw `getEventRunsIncludingIgnored()` is only for the controls that put a pass back: edit-run, the ET Finals standings (its pass log shows thrown-out passes with *Count again*) and `/api/runs?include_ignored=1` for the Runs page's Show Ignored and ET Finals' Round Review — plus add-pair, which copies one row's event metadata. New readers of runs use the visible path.

### Timestamp AM/PM inference (central domain quirk)

CompuLink emits timestamps **without an AM/PM marker**. `inferAmPm()` (scraper.ts) and `tagRunTimestamps()` (db.ts) reconstruct it by walking each day's runs chronologically: start in AM, flip to PM at the noon crossing (hour hits 12, or drops e.g. 11→1). A large amount of downstream logic (schedule, round ordering, "recent runs") depends on this ordering being correct — be careful editing it. Related: 4-wide ("quad") rounds get bogus timestamps for the second pair; `parseRunsFromHtml` repairs these, but **only** for rounds `detectFourWideRounds()` confirms are genuinely 4-wide, so normal 2-wide pairs aren't mis-merged.

### Race days (one event, several unrelated days)

One event's stored runs can span days that reuse the same round labels. getresults listed a track's previous weekend under the new event's date dropdown: D3 event 38 (Lucas Oil 10/07/2026) holds 10/02–10/04 from the weekend before (Q1–Q4, E1–E6), a 10/06 test day, a 10/07 evening session run as E1–E3, and the real 10/08 eliminations. Practice days run as E1 too (why ET Finals has `scoreFromDate`/`excludedDates`). The round name can't tell these apart; the day can. `src/lib/race-day.ts` (pure, client + server): `raceDayOf()` is the date of the AM/PM-tagged timestamp — a pass marked AM before 6:00 counts toward the night before, so a round run past midnight stays whole — falling back to the row's `start_date` when the timestamp has no date. `resolveRaceDay()` reads a `race_day` param: `YYYY-MM-DD`, `all`, or by default the latest day **the report's own rounds/classes** ran (not the event's latest day, so it never opens on a day they didn't run). Best Losing Package, Perfect RT and Dead On take `race_day`, return the day applied, show each pass's date, and share `RaceDayPicker`; `/api/runs` filters list the days. Event-level views (winners, qualifying, ladders, brackets, Data Out) still span every day inside the window, so a midweek session's E1 still mixes in there.

**Scraped runs are stored only inside the event's date window** — `eventWindow(start_date)` = the test day before through `start + 5` (getresults has no end date; that covers a Wednesday-to-Monday national plus a rain day). Every scraper ingest path (fetch-data, public-fetch, tech-noshows, backfill route and script) goes through `storeScrapedRuns()`, and `/api/live-runs` filters the same way. Event 38's grid carried all 1,742 passes of the Midwest Nationals (MI1, same track, 10/02–10/04). An out-of-window pass goes to another event only when exactly one event in the app covers that day *and* already raced that class that day; a pass it already holds needs nothing, anything unproven is skipped and logged. EData/CSV/add-pair (user-dated) are not windowed. Runs already misfiled are moved, never deleted, by `/api/misfiled-runs` (GET = dry run per day; POST `{action: "move"|"restore", confirm: true}`) or `npx tsx scripts/misfiled-runs.ts <code> <season> [--move|--restore]`: each batch doc's out-of-window rows are copied to `misfiled_runs/{event}_{season}/batches` and taken off the doc in one atomic write, and restore writes them back.

### Client data flow

The app is effectively a client SPA. `LiveDataProvider` (React context, `src/components/LiveDataProvider.tsx`) stores the live event config — **including the user's NHRA username/password** — in `localStorage` (`timindata_live_config`) and polls `POST /api/fetch-data` every `intervalSeconds`. Credentials are sent from the browser. Pages read everything else from `/api/*` route handlers, which call into `db.ts`.

`layout.tsx` → `LiveDataProvider` → `AppShell`. `AppShell` renders `Navbar` + `EventBanner`, but hides that chrome for the setup screen (`/` with no config) and the standalone `/day/*` and `/share` pages. `page.tsx` shows `SetupFlow` when there's no config, else `Dashboard`. The full feature list is the `NAV_ITEMS` array in `Navbar.tsx`.

### Public sharing (no client credentials)

`/share` + `POST /api/public-fetch` scrape using the **server-side** `NHRA_USERNAME`/`NHRA_PASSWORD` env vars, so a read-only schedule can be shared without exposing credentials in the browser. It refreshes the most-recently-scheduled event and enumerates the event's date dropdown to fetch every day.

### Tech Cards → Contacts & Mailing

- Stored in the `tech_cards` Firestore collection, keyed by **`member_number_category`**. Member number is the stable identity (a racer's car number changes between events), with car number as fallback.
- Populated two ways: (a) **spreadsheet upload** via `/tech-cards` → `parseTechCardWorkbook` (`src/lib/tech-card-parse.ts`); (b) **bulk scrape** via `/tech-card-backfill`, which pulls from two sources — the Tech Card Viewer site (`src/lib/techcardviewer-scraper.ts`) and racefiles Compulink Excel exports (`src/lib/racefiles-compulink.ts`).
- **`/contacts` (Contacts & Mailing)** reads `GET /api/tech-cards?all=1` and **collapses many tech-card rows into one `Contact` per person** (by member number, merging categories/email/phone/address). It offers year/category/division/event filters and bulk actions: print **mailing labels** (opens a print window with a 3-column Avery-5160-style grid), **copy emails**, **copy phones**, and a **mailto bcc** link. It's a fully client-side page — no contacts-specific API route.
- Tech cards also feed no-show detection: `getMissingFromEliminations()` in db.ts cross-references entered cars against actual runs, matching scrape categories (e.g. "SUPER STREET") to tech-card class codes (e.g. "SST") via `CATEGORY_CODE_TABLE`.

### ET Finals Points D1

Team points for the Summit Racing Series E.T. Finals / JDRL divisional championship, at `/et-finals`. Everything the chase needs is on that one page — rosters, tech cards, EData import, track names, class setup and the standings — so the setup isn't spread across `/tech-cards` and `/dataout` (which still exist for their own workflows).

- **Rosters** — uploaded on the page and parsed by `parseEtFinalsRosterWorkbook` (`src/lib/et-finals-parse.ts`) into the `et_finals_rosters` collection, one doc per `{season}_{trackCode}`. The 2026 combined workbook (sheets `Team & Instructions`, `Summit ET Roster`, `JDRL & Jr Street`) is only one of the layouts these arrive in — 2025 filed the E.T. team as its own workbook with the juniors kept separately — so `findRosterSheets` scans **every** sheet for a roster-shaped header instead of relying on sheet names, classifying each as big cars or juniors from its own columns (a DOB / age-group / JR-licence / parent column means juniors), and a junior row on a mixed sheet is caught by its age-bracket class. Prose sheets are excluded by name (`instruction|note|compliance|rules|…`) and by requiring 4+ distinct roster columns in one header row — without that guard the instructions tab's rules text parses as five extra racers per file. Every Summit E.T. entry scores; on the junior sheet only rows 1-10 score, rows 11+ enter but never earn. The parser repairs Excel's date-mangled age brackets (`12-Oct` → `10-12`) and stamps a resolved track code onto rows that left the cell blank.
- **Divisional flat roster (D4 layout)** — Division 4 files the other way round: one workbook for the whole division with a single **`Main Event`** sheet listing every racer, and a **`Team Code`** column (`A1`, `A2`, `C1`, `TV2`, …) naming the team. A track fields one to three teams, so the **team code is the team identity** (it becomes `track_code`, with `team_name` "Ardmore Dragway A1"). `parseEtFinalsRosterWorkbooks` (plural) detects this by a roster header carrying a team-code column and returns **one roster per team code** from that sheet alone — the per-track tabs, `Index`, `ROC` and `JS-HS-Man` repeat the same people and reading them too triple-counts (that's what the per-workbook path did when the file first arrived: 1332 entries under one team named after a header cell). Per-track tabs are consulted only for the captain. The same racer is routinely on two teams in two classes (Pro ET on A1, Super Pro on A2), and `(2)` on a name is Excel's mark for the second entry, not a second person, so it's stripped. Matching resolves the cross-team case by class: `classPreferred` in the engine keeps the roster entries whose `category` best fits the run's timing-system category (`categoryAffinity`, word overlap ignoring `ET`/`BRACKET`), as a preference not a veto. Divisional car numbers are the racer's real competition number and take no track suffix. The same roster also arrives as a **Compulink tech-card CSV** (`Category, Class, Car Number, Member #, First/Last Name, …, Crew Chief, Team Code`) with **no track column** — the team is spelled out as `Tulsa Raceway Park-Team 1-TR1` in the repurposed Crew Chief field. `findTeamLabelCol` finds that column by its values (the one whose cells end in the row's own team code) rather than its header, and `splitTeamLabel` yields the track name plus the `Team 1`/`Team 2` part, so a lone team is "Tulsa Raceway Park" and a track with two is "Ardmore Dragway Team 1"/"Team 2". The car column there must be found as `Car Number` ahead of `Vehicle Model`/`Body Type` — the loose `vehicle` alias otherwise files every racer under their car's model name. Rows with no car number, placeholder cells (`N/A`, `Open`, `No ET`) and a row whose track disagrees with its team code are reported in `warnings` and shown in the upload result.
- **Scoring** — `computeEtFinalsStandings` (`src/lib/et-finals.ts`, pure, no firebase import) gives 1 point per **main-race** round win and freezes a racer's points at their first main-race loss. Winning the buy-back puts them back on track but never back on the points board, so their later main-race wins score nothing (`racedAfterElimination` marks them). Big-car and junior points are tallied separately; the overall standing is the two combined.
- **Class setup** — which timing-system class is the main race, the buy-back, or not scored at all is per-event config in `et_finals_configs` (`{eventCode}_{season}`), along with each class's points board (big/jr). Saving also folds those choices into `et_finals_class_defaults/{season}`, remembered **by class name across every event that season**, so the next race opens already configured. Resolution order per class: the event's own choice → the season default (labelled *(remembered)*) → a name-based guess (*(auto)*). Buy-back classes are optional — some events don't run one. A track that runs the second chance inside the *same* class uses the per-category `buybackRounds` list instead: because the buy-back is nearly always a second session of round 1, the bought-back cars carry the same round code as the main race, so a listed round is read **per racer** — their first pass in it is the main race and every later pass is the buy-back. A listed round in which nobody has two passes is taken whole (a round only the bought-back cars ran). Either way the buy-back pass never scores, not even with "buy-back winners keep earning" on.
- **Tech cards as the identity bridge** — the divisional E.T. export (`TCET_*.xlsx`) uses its own column names (`carbikenumber`, `nhramember`, `drivername_first`/`_last`, `bracket`) plus a **`trackteam`** column naming the team the racer entered under; `parseTechCardWorkbook` reads both that and the racefiles Compulink layout. Its car number is the racer's *personal* number, not the roster-assigned team number, so a roster entry is indexed under both. A car the timing system's database doesn't know shows up on getresults as a bare number with no driver; the engine takes the **name off the tech card filed under that car number** (or member number) so the racer reads as a person and can still find their roster row by name — flagged `nameFromTechCard` on the unmatched row and on `matched_from`, and shown as *"probably — name from tech card"*, since it's a likely name rather than a confirmed one. `trackteam` **places a racer on a team** when no roster entry claims them (`source: "tech_card"` on the racer, and the team is created even with no roster on file), and otherwise acts as a tiebreaker. The roster still wins wherever it has an entry — `trackteam` disagrees with the submitted roster often enough (9 of 65 in the 2026 sample) to not override it. A **junior** placed this way starts **ineligible**: only roster rows 1-10 score and without that roster there's no way to tell which ten, so they're switched on per racer with the eligibility override.
- **Matching** roster entries to runs is **name-first**: manual pin → member number (via tech cards) → name → car number, scoped by division first because a junior `1LV` and a Super ET `1LV` are different cars. What the timing system shows is authoritative — the number a racer actually runs often isn't the one the roster assigned them, so matching on the car number first would put a racer's round wins on the wrong team's board whenever a stale roster number has been reassigned. A key held by two *different people* is never collapsed: candidates only merge when they're the same name, same generational suffix, same team and same eligibility, so a father and son entered at one track stay apart. **Two membership numbers settle it outright** — a racer holds one NHRA membership, so two of them under one name is two people whatever the names say (the reverse does not hold: a junior races on a parent's membership, so one number can cover two people). That applies on the run side too: a row already holding one membership number never absorbs a different one, it gets a row of its own on the same team. The **JR / SR suffix** is kept out of every key (one source writes it, the other doesn't) and used as a veto instead — where both the run and the entry state one and they differ, no route may join them. Once a class's points board has been set, a name that matches only the *other* board is reported (`reason: "other_board"`, with the entry named) rather than merged, since a same-named father/son across the two boards is the commonest collision and juniors race on a parent's membership; the cross-board fallback survives only for a class whose board is still an auto-guess. A key that spans two teams is resolved by the tech card's `trackteam` when that singles one out, and otherwise reported as unmatched rather than guessed; the page lists every unmatched racer with a picker to pin them onto a roster entry (stored in `manualMatches`, keyed `{category}|{carKey||nameKey}` → `{trackCode}|{division}|{slot}`), and flags any racer whose roster car number differs from the one they're running. Every identity folded onto a roster row is listed in the team drill-down with a one-click **Split off** button (a `TEAM|{code}` pin, so the car keeps its points with the team) and a **Move to…** picker for anywhere else. A page-level **Combined rows** panel above Unmatched gathers every such row from every team so a wrong merge doesn't have to be hunted for team by team, with the ones that look like two people (two membership numbers, or two names) sorted first and flagged red.
- **Car-suffix rule** — `trackCodeFromCarNumber` reads the trailing letters of a car number as the team (D1: `40ID` → ID), which places a racer no roster claims. Divisional (D4) numbers are real competition numbers whose letter means nothing, and with an `R` code known from anywhere every `…R` car landed on a phantom team R. `carSuffixNamesTeam` in the config (`boolean | null`) gates it; null = auto via `rostersUseSuffixedNumbers` (on when any roster entry's `car_number` is its `vehicle_number` plus a code, off otherwise, on with no rosters). The toggle sits with the race-day rules on `/et-finals`; standings return the applied and auto values for its label.
- **Hidden teams** — `hiddenTeams` (team codes) in the same config keeps a team that doesn't belong at the event (a stale roster, a tech-card code nobody races under) off the board: the engine still matches its racers to it so nothing spills onto another team or into Unmatched, but returns it in `hiddenTeams` instead of `teams`, so it's unranked and out of the totals, outlook and exports. Hidden from the team drill-down ("Hide team"), restored from the Hidden teams panel under the standings table. Saved with named setups.
- **Eligibility overrides** — `eligibilityOverrides` in the same config (roster entry key → boolean) forces a racer's points eligibility on or off when the roster sheet has it wrong, toggled per racer in the team drill-down. Everything that reads eligibility goes through `isEligible()` so an override applies to scoring, the roster counts and the exports alike.

### Data Out (`/dataout`) — EData import (timing-system fallback)

`/dataout` (formerly `/edata`; the old path 301s) is every Compulink file that leaves the app plus the EData import. The import half loads elimination results straight from CompuLink StarTrak **EData** files (`C##EDAT.TXT`) — the timing system's own export — for when getresults is down or lagging. Parsed by `parseEdataFile` (`src/lib/edata-parse.ts`), posted to `/api/edata`, stored through the normal `insertRuns` path.

- **Winners are implicit in the ordering**: within a round the rows are consecutive pairs, winner first; a bye is a lone row followed by a `SINGLE,<member#>` marker. Verified against the sample files by re-deriving every winner from the timing data (breakouts, red lights, no-shows) — 140 pairs, zero disagreements. The parser writes `result` `W`/`L` explicitly so nothing downstream re-derives it.
- Twelve comma-separated fields: car, member #, class, qual pos, driver, city/state, vehicle, engine, RT, dial/index, ET, MPH. Files are DOS-era (CRLF plus `0x1A` padding) and read as **latin1**.
- EData has **no clock times and no lanes**, but the rest of the app identifies a pass by its timestamp (dedup keys, pair grouping, ordering all use it). Each pass therefore gets a *synthetic* timestamp derived only from round + pair position + a per-category offset, so both cars in a pair share one and a re-import reproduces it exactly (idempotent). These are ordering markers, not wall-clock times — the page says so.
- **`dataSource: "edata"`** (LiveConfig, switchable in the navbar or on the page) stops `LiveDataProvider` polling entirely, so nothing from getresults or the API can overwrite the imported rounds.

### AccuTime export (timing computer → Compulink package)

`/dataout` also ingests **AccuTime's own session files** and builds the whole Compulink package in one go — QDAT + EDAT text plus a StarTrak qualifying PDF and the Final Round Results PDF. `POST /api/accutime-export` (multipart) → `parseAccuTimePack` (`src/lib/accutime.ts`) → `buildAccuTimeArtifacts` (`src/lib/accutime-export.ts`).

- **Inputs**: `race.acc` (a zip of the rest), `race.dat` / `Drivers.dbf` (both **Jet/MS-Access** DBs read with `mdb-reader`, which is in `serverComponentsExternalPackages`), `race.qly` (CSV qualifying order), `Class.ini` (class code, race date, series). The **`.acc` is password-encrypted by AccuTime** and can't be opened here — the parser detects the encryption flag and tells the user to upload the loose files or the text export (that gap is by design, not a bug).
- **Unlocked text export** (what Mike Rice emails: one zip, a folder per event, a folder per class) carries the same tables as CSV: `YYYYMMDDHHMMSSdat.txt` = the Logging table with a header row (times **truncated** to 2 decimals), `YYYYMMDDHHMMSSqly.txt` = the `.qly`, `Driversdbf.txt` = the Drivers table (quoted fields hold line breaks — Papa parses it). Files are recognised by content, not name; `__MACOSX` / `._*` / `.DS_Store` are skipped and zips inside zips are opened. There is **no Class.ini**: the class comes from the class folder's name (`classCodeFromName`: "Funny Car" → FC, "Stock" → STK, "Comp Eliminator" → COMP, a bare or bracketed code), the race date from the 14-digit **race stamp** in the file names (the same value Class.ini keeps under `[Race Date]`), and the series line from the page's sheet header — nothing invents it; a note asks for it, and typing it rebuilds the package (the series line is part of the built-header key with the logos). Low ET takes the `.qly`'s full-precision ET when it's the same pass (3.8599 → 3.860, not the truncated 3.850).
- **One event per pack**: every session carries `raceId` (the stamp) and `eventFolder`. A drop holding two events (Mike's zips often span two weekends) comes back as `choice: {kind: "event"}` and the page re-posts the same files with `event_pick`; a drop whose race stamps don't match the pack's comes back as `choice: {kind: "pack"}` — **Start a new pack** (`pack_mode=replace`) or **Add anyway** (`merge`). National class numbers: **Pro Mod = 5, Factory Stock Showdown = 16** (Jr Dragster / SMC's slots at divisionals); Nostalgia Pro Stock has none and takes the lowest free number. `assignCompulinkClassNumbers` (accutime-points.ts) hands the numbers out for **both** exports, fixed numbers first — otherwise a numberless class sorting ahead (Jr Street) takes Pro Mod's 5.
- **Drops accumulate by class** — Mark uploads one class at a time, so the page keeps the parsed sessions (`sessionsFull`) plus the built result in **IndexedDB** (`timindata_accutime_pack`; the base64 PDFs outgrow localStorage) and posts them back as `prior_sessions` with every request. The server merges by class key (code, else name — `mergeAccuTimeSessions` in accutime.ts): new class adds, a re-dropped class replaces only itself, and every artifact (EDAT/QDAT/points/PDFs/IDX) rebuilds from the full merged set. With prior sessions and **no files** the POST is a pure rebuild, which is how class pick / series header / logo changes apply — including after a refresh, when the original File objects are gone (`applyAccuClassPick` moves a late class pick into stored sessions *and their runs' `category`*, the EDAT grouping key). **Clear data** (confirmed) wipes the pack; header logos live in their own localStorage key and survive it. Regression checks live in `scripts/accutime-fixture-check.ts` (`npx tsx scripts/accutime-fixture-check.ts` — it also holds the MI1 2026 FSS case for both exports, checked against the tower's C16EDAT; set `MIKE_TEXT_ZIP` to Mike's 2026-09-18→27 zip to add the real-data structure checks — it holds racer PII, so it isn't committed).
- **Round detection**: `race.dat`'s `Logging` table counts qualifying sessions and elim rounds on the same `RoundNumber`, and the calendar day alone doesn't separate them — alcohol/sportsman classes run Q1 and E1 the same day, and a round stopped by curfew finishes the next day (2026 GL TAD/TAFC/TS/FSS). `splitQualElim` cuts each round's passes into **segments** (new day, a gap over an hour, or a pair that already ran coming back after 15+ min); the **last segment is the elim round only when the ladder holds** — round 1 re-fields cars that already ran or its winners make up round 2; later rounds follow the previous elim round in number and time with ≥80% of its cars being that round's winners. Earlier segments sharing no car with it that fit the same ladder are the rest of a split round and join it; the remainder is qualifying (consecutive disjoint segments = one interrupted session). Placeholder `LEFT`/`RIGHT` cars and all-bye passes are dropped. Ambiguous cases are surfaced as warnings (shown under the class on the page), never guessed silently.
- **Reaction times** are raw tree values; the tree base (0.4 pro / 0.5 full) is **inferred** from the RT spread and reported in a warning. Finish line (1320/1000/660) is chosen per class from the deepest non-zero times (nitro runs to 1000). `Drivers.dbf` `MakeOfCar` holds the two-digit body year, `ModelOfCar` the model. Byes are literal `BYE` rows (a `BYE` car number can still carry a driver name and times — still a bye).
- The EDAT/QDAT builders and tech-merge in `edata-export.ts` are reused verbatim (the finish-line ET/MPH ride in the `ft1320`/`mph_1320` slots so EDAT prints them). The EDAT is written from the session's own winner-first pairs (`buildEdataExport`'s `rounds` option), not re-paired from timestamps, so the text and the finals PDF list the same pairs in the same order. Session `Drivers.dbf` rows are trusted as current-event tech cards and merged with the shared store. The PDFs (`src/lib/racedata-pdf.ts`, jsPDF) are ported from Mark's `racedata-zip-to-pdf` playground — same coordinates, dotted rules, "WINNERS of each pair appear First" note, class order. Validated against the pack's own `refs/C2EDAT.TXT` / `C13QDAT.TXT`.
- The same page also **exports the other way, from getresults** ("Export from getresults — EDAT / QDAT / points / PDFs"): `buildDataOutArtifacts` (`src/lib/dataout-export.ts`) turns the event's **stored runs** into the tower's RACEDATA package — `buildDataOutExport` (`edata-export.ts`) gives `C#EDAT.TXT` per class with eliminations, `C#QDAT.TXT` per class with a qualifying sheet, `C#AyyDP.TXT` points files when a **points race code** is given (the tower's own event number, typed on the page — LO1-7 2026 is `17` though getresults calls it 18; a numeric event code is the default), then the StarTrak qualifying PDF and the Final Round Results PDF through `racedata-pdf.ts`. It was audited field by field against 15 events' tower packs (2026-10-09; results in PR #133), and every rule below reproduces something those files do. The audit re-runs with `scripts/dataout-parity/` (read-only snapshot of production → offline replay of the export → field-by-field comparison and a verdict for every remaining difference; the tower packs carry racer names, so they live outside git in `.dataout-parity/` — usage in each script's header). Served by `POST /api/dataout-export` `{event_code, season, categories?, pdfs?, series_header?, logos?, class_numbers?, points_race_code?, pro_scale?, incomplete_race?, timing?}`.
  - **Which runs** (`selectDataOutRuns`, `dataout-runs.ts`; nothing is moved or deleted, every leave-out is a warning): passes outside the event's date window (`race-day.ts`; D7 2026 event 74 held the whole Winternationals); where a class ran **round 1 twice** with the same cars, the other race of a doubleheader (LO2-4's Friday juniors — the race starting on/after the event's start date with the most elimination passes is the event's own); elimination passes dated before the class's round 1 (event 15's race-4 Stock final).
  - **Tower dialect**: `detectTimingSystem` — literal `BYE` cars or a null Q Pos on most rows mean **Portatree** (LO1-3, LO4-1, BL1), otherwise Compulink; overridable on the page. Portatree headers say `Portatree`, times are unpadded and **cut down** to 3 decimals (raw `0.11881` → `0.118`, a red light `-0.02348` → `-0.024`; the QDAT ET-minus-index is cut toward zero), a missing time is `0.000`/`0.00`, a finished pass with no RT `-0.500`, a blank Q Pos stays blank, the bye marker is `SINGLE,<member>,,,,,,,,,,`, every round including the final is headed `ROUND n`, a class with no designation prints a blank class, QDAT header lines right-align the car to 5 and heads-up rows print ET, MPH, ET. Compulink: `fmtRt` puts the sign against the digits (` -.021`), byes are `SINGLE,<member>,,0,,,,,,,,`, and downloaded EDAT/QDAT are **padded with Ctrl-Z to a 128-byte record** (`racedataFileText`; Portatree files carry none).
  - **EDAT**: the empty lane beside a bye (a blank car, often with junk text in the name field, or a `BYE` car) is never a racer; a car stored twice in one round (the same pass under two clock times, or an empty copy) keeps one row (`collapseCopiedPasses`); the class column is the car's class (`C/DA`, `E/SA`), the code only when the row has none; the Q Pos column is getresults' own, else the racer's position on the class's QDAT (round-1 rows of a Super class always take the sheet's, 0 for a round-1 loser); getresults' no-time stand-ins (`99.999` ET, `1.00` MPH) and a lone-digit dial print as nothing; a class whose whole field runs one index (SC 8.90) prints it where a row has no dial; the finish line is the quarter or the eighth **by majority** (two junk 1320 readings no longer blank an eighth-mile class). **getresults never codes a final `F`**, so `elimRoundsForCategory` marks the last round final when it has one pairing and the previous round's winners are its two cars (or that round had two pairings, or a two-car class raced only the final); a lone non-winner row (stored test junk) doesn't block it.
  - **QDAT** — the class decides the sheet (`qualStyleFor`), not the dial-in column (getresults puts dial-ins on Top Dragster qualifying passes): **Super Comp / Gas / Street don't qualify — the tower's sheet is their round-1 winners** ranked closest over the index (breakouts last), which ladders round 2 (no Low ET line, ET right-aligned to 6; getresults' T rounds never count); Stock / Super Stock / Comp furthest under the car's index over the Q sessions, **QC and C1** (the first class-elimination round counts, C2+ never do), a pass with no dial taking the car's other qualifying dial, else its designation's; pros, alcohol, TD/TS and other heads-up classes quickest ET with that pass's MPH and the best MPH in the last two columns; juniors, JDRL and Sportsman Motorcycle **best reaction time** (RT in the ET column, a 4-space index; Portatree juniors rank on ET and print `0,0`); a class the tables don't know qualifies against an index only when ~every pass carries one. Passes are read at the class's own finish line, as the EDAT reads them (an eighth-mile pass can carry a stray 1320 reading — BM1 2026 Outlaw Street). Ties compare in thousandths and go by run order — on a heads-up sheet the higher MPH first (26 of 26 ties on the Compulink sheets), which also picks between a car's own equal ETs. A qualifier with no timed pass is still listed, last: a run that never timed prints getresults' `64.999` with the index and the difference, no reading at all prints `28.000` on a Compulink sheet (index and difference, or `00.00` speeds — the convention on 18 lines across 11 packs) and zeros on a Portatree heads-up sheet. **Once eliminations are on file their rows carry the tower's own ladder numbers** and pin the sheet (`pinnedSheetOrder`; a Super class's from round 2); the other qualifiers fill the gaps only where their pass fits between the neighbours, and one whose pass would beat a pinned racer goes to the bottom — that's a DQ, which getresults never shows. Before eliminations: the latest Q Pos, then the rule — unless getresults repeats a position (BM1 2026's pro classes after Q4), when the rule orders the whole sheet and a warning says so. Car numbers no row names or classes aren't on the sheet. `Low ET` is the #1 qualifier's line (the tower's own line has no single definition — that fits 72 of 120 classes); `Top Speed` the best MPH of the sheet's passes. The event's qualifying setup (`qualifying_config.classMode`) still overrides the rule for any class but the Super classes.
  - **Class numbers**: a C# pinned on the page per class (kept per event in localStorage `timindata_dataout_prefs` — the tower numbers juniors, shootouts and other extras however its operator set them up, so only the user can supply those), else `assignCompulinkClassNumbers` (fixed numbers first; the national tower's special slots — 2Fast2Tasty TF/FC/PS/PSM 17/21/25/29, snowmobiles 22, Outlaw Street 24, JDRL 27, Sox & Martin 28 — matched by name ahead of the cars' FC/TF codes), else the lowest free number.
  - **Points** (`buildDataOutPoints`): the same rounds the EDAT prints, scored by `scoreAccuTimeSession` (sportsman bracket by the **round-1 field**, alcohol qualifying + attempt points, the pro national structure — picked by the **class name**, since a junior class's rows can carry the tower slot's code: LO2-4's Advanced JR rows say `PSM`), 10 entry points for every named entrant who ran the class but not its eliminations — except a qualifier the QDAT puts inside the round-1 field who then didn't race it, who takes the round-1 loss points. Rows go as the towers list them: racers by the round they reached (ties in round-1 order), then everyone who never raced in one block — the towers' entry order, which isn't in the timing data, so the app uses run order; no file for a class whose final isn't on file. The division column is the tech card's home division, 0 without one (state doesn't settle it — divisions split states, and national packs print `A`). Header `Compulink StarTrak EVENT Points for <CLASS> w/REG code 1` (the REG code varies by tower); Portatree's ends `End of File ` + 106 Ctrl-Zs. IDX14 isn't produced from getresults: it's the tower's own class database (index and record for every Stock/SS class, past champions), none of which is in the timing data.
  - Entry fields merge from the tech cards as before (car number → exact name → first initial + last name, every stored card readable, other-event cards only where the name doesn't contradict); the body is the **model alone** (`'06 Cobalt` — the tower includes a make in 2% of bodies, mostly "Chevy II"), names drop the period from Jr/Sr. Pairs are winner first; `findSupersededCopies` still drops a pass getresults moved to another round (see Gotchas). The page: import tech cards → class checklist with an editable C# per class, points race code, pro scale, tower format → **Download text** (one file, or `RACEDATA.zip` with QDAT/EDAT/points toggles) and **Download PDFs**.

### Track directory

Track codes (`LV`, `ND`, `MG`, …) are the team identity everywhere — but roster templates often arrive with the track-name cell blank and a tech card only ever gives the bare code. `et_finals_tracks/{season}` maps code → `{track_name, team_name}`, edited in the **Track Names** panel on `/et-finals` and applied to the rosters *before* scoring so the chosen names flow through standings, drill-downs and exports alike. Codes are gathered from both rosters and tech-card `trackteam` values, so a code can be named before its roster arrives. A roster filed under the wrong code (the blank-cell case, e.g. Numidia landing under a filename-derived code instead of `ND`) can be re-keyed via `PATCH /api/et-finals/rosters`, which moves its entries' car numbers with it.

### Domain glossary

- **Rounds**: `Q*` qualifying, `E*` eliminations, `T*` time trials/test, `F` final (`roundSortKey` / `roundSortWeight` order them).
- **Categories** are NHRA classes. A category is treated as **bracket** vs **heads-up** by whether the majority of its elimination runs carry a `dial_in`.
- **Metrics on `RunRow`**: `rt` reaction time, `ft60/330/660/1000/1320` elapsed time at distance (1320 ft = the finish / ET), `mph_*` trap speeds, `dial_in`. Derived: **package** = `rt + (ET − dial_in)`, **breakout** = `ET < dial_in`.

## Gotchas

- **`firestore.rules` is wide open** (`allow read, write: if true`). There is no auth at the database layer.
- **A pass getresults moves to another round is stored twice.** The round is part of the dedup key and `collapseNearDuplicatePasses` only merges copies within one round, so the old copy (MI1 2026: two FSS Q2 pairs still filed as E1) stays in the store. Only the Data Out export filters it (`findSupersededCopies`); ladders, schedule, stats and ET Finals scoring still see it.
- Scraping API routes declare `export const dynamic = "force-dynamic"` and return no-store cache headers. This is deliberate — defeating Next.js's data cache fixes a recurring "Refresh Data returns yesterday's runs" class of bug. Keep it when adding scrape endpoints.
- `firebase-admin` is listed in `serverComponentsExternalPackages` (next.config.mjs). `db.ts` and `firebase-admin.ts` are server-only.
- **Tailwind theme lives in `globals.css`, not `tailwind.config.ts`.** This is a CSS-first Tailwind v4 setup: the live tokens are the `@theme` block in `src/app/globals.css` (which also defines `nhra-accent`/`green`/`yellow`/`orange`, absent from the JS file). `tailwind.config.ts` is dead — v4 doesn't auto-load it (no `@config` directive), so editing it does nothing. Add/change colors in `globals.css`.
- **The light theme is class remaps, not tokens.** v4 drops scoped redefinitions of the `@theme` colours, so `[data-theme="light"]` rules in `globals.css` override the generated utilities one by one (surfaces, borders, white/gray text, the pale status text shades, recharts' SVG fills). A colour utility with no remap there renders its dark-theme value in light mode — add a remap, or use the `light:` variant (`light:bg-white/85`) for one-off markup. Those remaps are unlayered, so they also outrank `hover:` utilities; the hover colours are re-asserted in the same file. Fonts are `next/font` variables set in `layout.tsx` (`font-sans` Inter, `font-display` Barlow Semi Condensed — h1/h2 get it on screen — `font-mono` JetBrains Mono). Print keeps the system fonts, and the card/button depth rules are screen-only, so printed sheets don't reflow.
- Two different category classifiers coexist. The **bracket-vs-heads-up** distinction in the glossary is the dial-in-majority heuristic in `db.ts`; separately, `src/lib/categories.ts` (`classifyCategory`) regex-maps a class name to a `RaceFormat` (`bracket`/`index`/`heads_up`/`handicap`), used by the stats and racer-profile pages. They are independent — don't assume one drives the other.
